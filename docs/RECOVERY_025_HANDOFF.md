# Bridge0.2.5 — MCP恢复后的开发交接

日期：2026-10-12。继续既有R0–R6计划。**本轮实现共享标签页恢复与历史读取修复，并完成独立服务异常退出的隔离验证；没有切换正式3211，没有推广iOS候选。**

## 保留的范围和并行更新

只拆手机桥接，不移动原executor/3210/任务队列/PC状态增强。一个明确绑定的PC标签页与手机共用对话，手机每对话草稿本地保存、仅发送时提交。没有新增专用镜像标签或自动抢焦点规则。

恢复现场已有另一轮完成的Bridge0.2.4后台维护功能，原executor已是v44-background-reload。本轮保留该增量，不退回v43或前台设置页重载。`update-staged-runtime.mjs`现在自动后台重载；实测worker重启、版本0.2.5、连接恢复、活动标签不变、未刷新用户页面。

## 代码变更

1. `shared-background.js`：在绑定会话内缓存实际观察到的当前路由及历史搜索/列表链接；跨整页刷新仍可返回之前已识别的聊天。只缓存经过ID/官网路径校验的链接，不接受任意URL或未观察目标。缓存不包含消息正文、不落永久历史库。
2. 整页导航关闭旧消息端口时，短暂只读等待Chrome pending/committed URL确认，再重新订阅。绝不再次点击同一导航或重发消息；PC草稿冲突仍立即返回。
3. `shared-page.js`及`presentation.js`：首次连接时搜索弹层已经打开，也能读取实际渲染、但仅被应用外壳aria-hidden遮蔽的当前正文。仍排除隐藏旧会话、正文内隐藏分支、思考和工具区域；搜索状态不允许写隐藏输入框。
4. 增加有界historyLayout元数据，区分当前加载轮数和网页滚动范围；这是诊断信息，不代表已经实现官网未加载历史的自动补取。
5. `scripts/test-history-recovery.py`：实际MV3扩展和独立服务的7项恢复/历史测试。
6. Windows `run-service.ps1`及`service-control.ps1`：启动任务看护真实子进程、无执行时限、重复启动忽略；子进程退出后延迟2秒重启。计划停止先停看护任务，避免杀子进程后立刻拉起。正式任务注册逻辑已修改，**本轮未在3211注册/启用该任务**。

## Windows恢复验证细节

最初仅依赖Task Scheduler失败重启设置的测试没有按预期恢复，工具等待超时；本轮没有把该次算通过。清理隔离任务后，改为已有PowerShell启动脚本等待/重启唯一Node子进程，再复测通过。

最终结果：强制终止**测试端口13214的已核实进程**，约2.6秒后新PID健康上线。配对文件、扩展连接Key和一条人工unknown回执的SHA256保持不变，pending仍0，没有发送重放。重复启动未产生第二服务。原3210与测试13213保持运行；临时任务和监听已清理。

证据：私有 `var/service-recovery-result.json`；测试脚本 `scripts/test-service-recovery.ps1`；任务入口 `scripts/run-service.ps1`。只证明子进程退出恢复和任务配置，不宣称真实开机/断电恢复、正式迁移或回滚已验收。

参考Microsoft原生任务设置：New-ScheduledTaskSettingsSet / ExecutionTimeLimit；这里的无时限和IgnoreNew使用系统任务设置，子进程重启由轻量启动脚本执行，没有新编排框架。
