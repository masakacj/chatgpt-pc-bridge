## 3. 各阶段具体任务

### R0：保住成果，结束本地与仓库脱节

复用现有构建、源码导出及已验证发布路径，不再研究新的凭据传输或重搭网络。PC 当前源码仓库为 `masakacj/chatgpt-pc-bridge`，本地 `D:\workspace\py\chatgpt-pc-bridge`，workspace `ws_53924e782d`。已上传的旧代码 SHA `4403027299a8499989cc87b3cbd4b189ec51d168` 不能冒充本地最新修复。

新提交纳入所需 bridge 模块和部署脚本；`source-imports.json` 只能作为历史提取来源，不再依赖 Orchestrator 才能构建。严格排除 `var/`、密钥、配对、命令日志、浏览器资料、私人页面内容和测试录屏。以独立克隆构建检查文件完整性，并保留一个可回退的版本组合。R0 完成后，每项修复正常提交，不再积累长时间仅本地有效的版本。

### R1：先解决官网用户消息识别和回执

只读恢复已记录测试会话：用真实 conversationId／已观察的官网入口重新定位，不复用失效 tabId；查不到旧记录则保留“未确认”，不得把助手回复、编辑框清空或时间过去当成成功证据。

对实际页面的用户消息节点、角色标记、消息 ID／轮次、正文与分支边界做最小检查，提取去隐私的结构 fixture，修正 `extension/shared-page.js`，必要时小改 `shared-background.js` 和 `service/mobile-bridge.js`。不要为此修改整套 SwiftUI 或重构状态系统。

专项回归覆盖：现有聊天中文／多行消息、新聊天 DOM 先出现而 URL 后分配 ID、项目首条消息、刷新重新读取、同文案的旧消息不被误认作本次发送、点击前失败与点击后结果未知的区分。只在获得当前动作对应的新用户消息证据后确认；发送命令 ID 继续唯一，不进行网络级自动重发。

验收证据记录“点击次数、新用户消息数、实际会话/项目 ID、提取的消息角色与回执状态”，不把私人正文写入公共 handoff。旧未确认记录只读核对；确需新写入时，用明确标识的开发测试聊天和新的测试用例，不循环重发旧消息。

### R2：官网主流程，不用模拟通过代替

同一个绑定 tab 验证手机 A→B、PC B→C、新建普通聊天、项目内新建与首发、浏览器刷新和关闭；仅切换其他 Chrome 标签不能改变镜像目标。导航必须可以继续使用，不能因无关工作流忙碌全局锁住所有聊天；同页写入只做必要的输入/发送冲突检查。

历史检索使用官网真实搜索入口，选取至少一个不在当前已加载侧栏、以及一个项目内旧对话验证打开。核对继续加载、结束、无结果与仍在加载的区别，修正只要有结果就永远显示“更多”的情况。历史正文分页也检查顺序和连续性。归档等特殊入口只按官网实际可定位范围登记，不以有限列表冒充完整历史；不靠猜测链接或转向未约定的私有 API 赶进度。

项目新建需证明进入正确项目，首条消息产生真实 conversationId，不能无声退化成普通聊天。工具确认入口按实际可提取按钮验证一次；无法映射的网页复杂交互明确保留 PC 操作入口，不宣称全部兼容。

### R3：以现有原生版本收尾，而不是再造客户端

复用现有 `SharedTabDraftLedger.swift`、`SharedTabModel.swift`、`SharedTabScreen.swift` 与测试。保留已通过的 8 项 UI 和 24 项策略用例，仅给实际缺陷补回归；PC-only 小修不每次重建完整 iOS。

核对原生顶部/侧栏/输入框、安全区域、键盘弹起/点击空白收起、长文本输入、对话切换后的草稿、阅读旧消息时不被强行拉到底部、深浅色和较大字体。用同一段代表性长对话记录打开、切换、首次可输入、滚动与内存情况，区分本地卡顿和 PC 加载等待；没有变化的快照不重复触发大范围重绘。原网页只保留备用入口。

候选版必须先可签名安装，才能进入真机验收。复用现有签名能力，先输出独立 beta/候选安装条目，**不更新正式 latest**；若现有签名接口会自动上架，则最小化拆出“仅签名/候选”和“正式推广”两步。不要出现“签名前要求真机通过、真机前又没有可安装包”的循环。记录真正测试后的 SHA，不把 CI 触发前的 SHA 误记为最终测试源码。

### R4：只拆旧桥接，切到正式通道

先在已装新扩展＋测试服务验证 R1/R2，再进入空闲切换窗口。原工程只停用旧 mobile 初始化、消息转发与内嵌 3211；原 executor 扩展及 ID、工作流代码、任务队列、3210、PC resilience 不搬动。需要释放监听或重启原 Node 进程时，只在确认无执行中的任务且状态已保存后进行，不重启用户 Chrome。

迁移正式手机 pairing 和服务端 command journal，新扩展只衔接必要的 mobile 预约记录，不迁移原执行器全部存储；测试端口自身的测试配对不能覆盖旧手机正式配对。同一时刻只有一个正式 3211 写入者，保留原有 HTTPS/NPM/WireGuard/DNS 路线和 `/v1/` 地址。发布前继续核对双扩展无重复桥接/状态观察、原工作流未退化。

补齐 Windows 开机启动与**运行进程异常退出后的恢复**，不能把“启动脚本执行成功”当成常驻恢复完成。用一次故障恢复和一次回滚演练验证：只恢复桥接，旧命令不重发、配对不丢、3210 继续可用。沿用简单的进程管理能力，不为此增加新编排服务或分布式锁框架。

### R5：真机验收，发现一项修一项

使用已签名候选版和真实正式通道，核验手机选择绑定页、历史/项目切换、新建、首发、回复、确认按钮；电脑页内导航手机跟随、电脑切其他 tab 不劫持绑定。

再覆盖 Wi-Fi/蜂窝切换、后台/恢复、App 重启、PC 标签刷新/关闭、服务短暂离线/恢复、两端各自未发送草稿、失败后的回执核对和继续输入。覆盖安装保留配对、本地草稿及未确认记录，不要求卸载。

记录 iPhone/iOS、App 版本/Build、PC extension/service版本、测试结果与剩余问题。模拟器成功和设备目标编译成功不是此项完成证据；没有真实 iPhone 操作结果时保留待验收，不自行打勾。

### R6：发布、验证、归档

目标 iOS 0.7.0，Bridge 使用实际通过验收的修复版本，不预先编造最终 Build。将准确测试 SHA 合并/标记，通过现有流水线签名并推广；核对安装中心 GET latest、manifest、实际签名包及应用内版本，同时保留上一稳定签名版和 Bridge 回退组合。

最终 handoff 固定：两个仓库的准确提交、extension ID/安装位置、正式服务地址/端口与进程恢复方式、已通过测试、已知限制、安装方法和回退步骤。旧路线图标注历史，不让“0.1.0未开始”“需要executor adapter”“强制专用tab”等已取消要求再次指导开发。

## 4. 开发效率与完成判定

每个实际缺陷只补相关测试；每个里程碑做一次阶段回归，候选发布前再跑完整必要回归。不要为 PC-only 解析修改反复触发全部 iOS 签名流程，不重复扫描已知主机/目录，不反复更换架构。原生客户端不能因为桥接拆分而被改成网页容器。

每个阶段只更新一条可核对的记录：`阶段｜状态｜源码SHA｜运行版本｜测试环境/结果｜证据｜下一步`。状态限“未开始/进行中/阻塞/已验收/已发布”，不能把代码已写、模拟测试通过、真实官网通过和已发布混写。公共记录不含配对密钥、正文或完整私有日志。

全计划完成的标准是：独立桥接正式运行且原编排器保留；iOS 原生功能在真实手机/官网链路通过；可安装签名版正式上架；源码与运行版本一致；恢复/回退可用；交接完整。R1 用户消息未确认、R2 关键官网功能或 R5 真机验收未完成时，都不能以“主要代码写好”标记全部完成。

本次仅制定并保存后续计划；没有据此修改运行代码、停止服务、发送消息、触发新构建或发布 IPA。
